# 换面

一款让你重新理解扫雷线索的浏览器解谜游戏：数字 → 安全数 → 图形 → 概率 → 方向 → 空间 → 网页本身。打开所有安全格或调查所有安全元素即可完成关卡，雷位和规则在关卡中始终固定。

## 本地启动

需要 Node.js 20 或更新版本。没有外部运行依赖，也没有安装依赖或构建步骤。在本目录打开终端，运行：

```sh
npm start
```

浏览器打开 [本地预览](http://127.0.0.1:4173/)。按 Ctrl+C 停止预览。请通过本地服务访问，直接双击 HTML 文件可能无法加载 JavaScript 模块。

如果端口被占用，在 PowerShell 中运行：

```powershell
$env:PORT = '4174'
npm start
```

再打开 [4174 端口预览](http://127.0.0.1:4174/)。本地服务只监听本机，拒绝目录越界路径；它是开发预览工具，线上由 GitHub Pages 提供静态文件。

## 怎么玩

- 左键或 Enter 打开，右键或 F 记笔记；方向键移动焦点。也可以先选工具再点格子。
- 负形章的数字统计有效邻格中的安全格；角、边与内部的邻格数量不同。满安全数可以展开，0 安全数意味着邻格全是雷。
- 图形章依据公开模板、允许的旋转与摆放约束推理。个人笔记（雷旗与安全勾）都是假设，不能成为概率证据。
- 概率章采用公开的有限候选与均匀先验。未知格的百分比表示本格有雷概率，已开格的百分比表示未知邻域的平均雷密度。
- 无伤采样返回指定区域的真实雷数，并更新候选。两次是优秀评级参考，可以继续采样；不会因次数用尽而卡住主线。
- 向量章箭头指向最近的固定 2×2 雷簇中心，等距时保留所有方向；沿途的格子未必有雷。
- 空间章以固定世界坐标和半径定义邻居。旋转只改变观看方向，不能改变邻接关系。
- 第八章直接调查真实页面上的标题、按钮、说明、卡片区域与来源链接。这些元素作为固定关系图的节点，数字统计图中相邻元素的雷数；不是按屏幕上看起来近不近来计算。缩放或改变窗口尺寸不会换雷，也不会改变邻居。
- 网页调查只作用于明确列出的目标。提示、笔记、重开、帮助、关卡地图，以及网页章的离开、聚焦和关系图控制保持正常操作，不作为雷节点。离开调查后，页面元素恢复原有行为。
- 误开雷只确认该格并记录误判，保留其他进度。撤销仅影响笔记，已经公开的事实保留。
- 进度保存在当前浏览器；刷新可续玩。提示帮助解释公开证据，不扣命、不强制计时。

## 交付范围

本版共 8 个章节、25 关：18 关二维篇（数字 3、负形 4、图形 5、概率 4、综合 2），加上向量 3 关、空间 3 关与网页元素 1 关。空间使用精选的程序节点，没有导入高密度扫描点云；网页章 W01 使用页面真实元素与公开的固定语义邻接图。

这是可运行、可验算的首个网页版本。策划中的 45–60 分钟和真人理解率是待试玩目标；代码验证不能替代盲测。没有账号、在线排行榜、多人、随机关生成器或服务器存档。

## 验证玩法公平性

```sh
npm test
npm run verify
```

如果环境只有 Node、没有 npm，也可以运行以下等价命令：

```sh
node tools/serve.mjs
node --test
node tools/verify-levels.mjs
```

`npm test` 检查边角补数、负形展开、笔记不影响后验、采样与条件更新、精确的确定状态、存档恢复、相同证据下隐藏真值不影响概率、向量等距及固定半径邻接。网页章另验真实元素映射、核心控件排除、固定图不随布局坐标改变、调查存档及公开信息通关。静态服务测试直接调用实际请求处理器，覆盖编码路径、Windows 分隔符、HEAD 与错误响应；另有真实回环 HTTP 检查，在禁止客户端连接的环境中会明确跳过。允许创建符号链接的环境还会验证链接越界拒绝。

`npm run verify` 验证每张固定手工盘的完整解法，并对概率目录遍历全部初始合法布局和对应结果分支。每一步只根据公开候选选择确定安全格，或选择能区分候选的公开采样区域。它不会用真实雷名单决定下一步操作，逐步检查候选后验和零误判通关，失败时返回非零退出码。报告明确区分“固定关卡”和“全部分支”，不把其他假想手工盘的可解性算入发布承诺。

验算结果列出每关的候选峰值、采样数与操作数。固定盘只取当前出题布局的通关路径；目录关的最坏采样数是当前公开决策策略在全部目录真值上的最坏分支，并非最优策略证明。验算范围内的候选超过 4096 个会明确失败，不会把部分检查报告成完整验证。需要机器可读结果时运行：

```sh
node tools/verify-levels.mjs --json
```

本次具体结果和证明边界见 [玩法验算记录](docs/verification.md)。这些检查能证明公开信息下存在完整通关路径及规定的状态一致性，不能证明趣味、真人理解、设备交互质量或预估时长；对应体验仍需试玩。
