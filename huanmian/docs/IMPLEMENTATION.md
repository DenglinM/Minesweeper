# 《换面》实现范围与验证边界

本版为可在静态网页运行的扫雷认知实验。产品名称为《换面》，目录名为 `huanmian`。**当前没有真人盲测记录；不把自动检查等同于体验验证。**

## 内容范围

| 部分 | 关卡数量 | 定位 |
| --- | ---: | --- |
| 数字 | 3 | 建立八邻格和局部计数理解 |
| 负形 | 4 | 数字改为统计安全邻格 |
| 图形 | 5 | 公开模板和合法摆放约束 |
| 概率 | 4 | 公开候选、条件概率、无伤区域采样 |
| 综合 | 2 | 迁移前面建立的理解 |
| 向量 | 3 | 实验扩展：固定雷簇与方向线索 |
| 空间 | 3 | 实验扩展：固定半径邻接与分层观察 |
| 合计 | 24 | 18 关二维主线 + 6 关实验扩展 |

内容使用固定小盘、初始安全锚点及数据定义的公开约束。关卡地图允许自由体验，也建议按顺序游玩。向量和空间能够运行并接受规则验算，仍需要独立验证其教学、阅读与操作价值。

## 与策划相符的核心规则

- 每关雷位与邻接固定。新证据更新知识，不重新布雷。
- 目标为打开所有安全格；不强制逐一给雷插旗。
- 雷旗和安全勾只是玩家笔记，不进入概率和候选过滤的证据集合。
- 误开雷只确认这一格，记录误判并保留其余进度；不曝光整盘，不阻断继续游玩。
- 撤销只影响笔记。公开事实和采样不会因为撤销而被删除。
- 负形数字等于有效邻格总数减去雷数；包含已经打开的安全邻格。
- 图形章枚举公开模板允许的旋转和合法摆放，不依赖模糊图片识别；模板不跨边界、不重叠。
- 概率章将不重复的公开候选布局等权处理，只依据初始公开条件、打开结果和采样结果过滤候选。
- 未知格的有雷概率与已开格的未知邻域平均雷密度是不同量；后者没有未知邻居时无分母，应显示邻域已确认。
- 无伤采样返回区域真实雷数。两次作为优秀目标，额外采样仍可进行并记录辅助完成。
- 向量指向最近固定 2×2 雷簇中心，采用欧氏距离和八方向量化；等距时保留全部方向，包括同方向多个中心。
- 空间使用三维坐标的固定半径构建对称邻接，旋转和分层只改变显示，不改变推理事实。

## 明确的实现取舍

1. **空间素材是精选程序节点。** 本版没有导入用户扫描数据，没有把整片高密度点云直接做成扫雷，也没有做场景漫游、VR 或三维素材重建。
2. 图形章采用公开模板、候选图与数字线索，没有提供拖动图形叠影操作。策划中的拖动预览留待后续版本。
3. 候选目录采用小规模精确枚举和缓存；概率实现不承诺支持任意尺寸随机棋盘的全量后验计算。
4. 标准困难大盘、随机生成器、账号、排行榜、每日任务和多人模式不属于本版。
5. 数据与存档在当前浏览器保存，无服务器和跨设备同步。清除浏览器数据会失去进度。
6. 优先桌面浏览器的鼠标与键盘。页面提供小屏布局与工具选择，但完整触屏体验仍需专项检查。
7. 策划中的体验时长、200 毫秒概率更新和真人理解率均为待验证目标，不能从代码完成推导为已达标。

## 模块结构

| 文件 | 职责 |
| --- | --- |
| `index.html` | 页面布局、规则面板、工具栏、地图与完成对话框 |
| `styles.css` | 棋盘与状态表现、响应式布局、焦点和减少动效设置 |
| `app.js` | 页面事件、章节与关卡切换、棋盘渲染、存档、音效和空间观察 |
| `engine.js` | 事实、证据、候选、概率、采样、笔记、提示与通关判断 |
| `levels.js` | 章节、节点、固定雷位、邻接、锚点、模板和采样区域 |
| `tools/public-solver.mjs` | 只使用公开候选与采样区域的解题策略、结构及完整分支验算 |
| `tools/verify-levels.mjs` | 汇总关卡验算报告；失败时返回非零退出码 |
| `tests/` | 规则边界、笔记与证据、概率和本地服务器等自动测试 |
| `tools/serve.mjs` | 本地静态网页预览，不是线上游戏的后端 |
| `docs/PLAYTEST.md` | 人工界面检查与真人盲测记录清单 |

游戏运行采用浏览器原生 ES modules，静态文件可以直接发布到 GitHub Pages。Node.js 只用于本地预览和自动检查，线上玩家无需安装。

## 自动验算可以证明什么

验算器检查节点与邻接合法、初始点安全、真实布局属于公开规则、候选去重、概率等于候选频率。对预算内的每个初始合法布局，将其分别作为隐藏真值，使用只看公开信息的策略行动，检查能完成全部安全格且不依赖踩雷。

这提供配置公平性和数学可解性的证据。验算器报告的“最坏采样”是所用公开决策策略实测的最坏分支，**不是最优采样次数的数学证明**。唯一解也不能直接证明人类有清楚、简短的推理路径。

自动报告应与实际运行结果一起留存。发布记录只在对应检查完成后填写“通过”；不能因为存在测试文件而声称全部通过。

## 仍需人工验证

- 玩家是否理解负形、图形模板以及概率两个百分比的区别。
- 章节反转是否产生可复述的理解迁移，而不是重新阅读规则的负担。
- 概率章是否形成有效的信息选择，而不只是跟随百分比点击。
- 向量是否增加有趣推理，空间节点是否便于选中、定位与观察。
- 实际游戏时长、目标设备更新耗时、小屏和键盘操作、存储失败恢复。

执行 `docs/PLAYTEST.md` 后才能形成真人试玩结论。本版公开分享可收集反馈，不代表这些问题已经解决。
